# 外部图库目录监听与入库恢复

外部图库可以使用目录级监听覆盖全部导入根及未排除的子目录。新建或移入的子目录会递归注册；隐藏目录、图库排除规则和符号链接继续保持原有边界。事件按路径等待 5 秒安静期后入队。默认保留启动补扫与定时校验；NAS 可显式选择下面的纯手动扫描策略。

## 纯手动扫描与事件恢复

设置 `IMMICH_FORK_LIBRARY_SCAN_MODE=manual` 后，启动、重建监听和配置刷新均不自动扫描图库，定时全量扫描也不会启动。已有队列中的启动根目录补查会跳过，其它事件与手动任务继续处理。管理界面中“外部图库 → 对应图库 → 扫描”及原有扫描 API 保持可用。

通过 `IMMICH_FORK_LIBRARY_WATCH_STATE_DIR` 指定容器内的可写状态目录，并绑定到 SSD（NAS 使用 `/volume2/docker/immich/library-watch-state`）。目录中仅保存尚未获队列确认的事件路径，不包含原片。队列提交失败后每 5 秒重试；进程重启后只重放已记录路径，提交期间的新事件不会被旧批次确认覆盖。目录移动、新建嵌套目录和根目录替换会恢复相应监听。无法定位具体路径的事件只报告缺口，不在后台升级为全库扫描。

监听与入库仍属于 Immich，不由通用宿主辅助服务接管。整个 NAS 完全关机期间通常没有写入；需要留意的是 NAS 仍可写而 Immich 未运行，以及开机后写入服务早于监听就绪的窗口。已记录事件可以恢复，未被观察到的写入不能凭空恢复，应由管理员在需要时手动扫描。恢复监听仍需枚举目录以注册 inotify，但不会逐个检查所有已有照片。

## 配置监听范围

保留 `library.watch.enabled=false`，让 Fork 使用目录监听树，而不同时启动官方的全库文件监听。

- `IMMICH_FORK_LIBRARY_WATCH_ROOTS=all`：读取现有外部图库的全部导入根。
- `IMMICH_FORK_LIBRARY_WATCH_ROOTS='["/external/photos","/external/screenshots"]'`：只监听明确列出的根。
- 未设置新变量时，原有 `IMMICH_FORK_LIBRARY_WATCH_ROOT` 单根配置继续有效。

重复或嵌套根只注册一次。每个监听根必须唯一归属一座外部图库；配置变更需要重新启动 Server。监听范围仍受图库当前导入路径与排除规则约束。启用前应检查目录数量、当前 inotify 使用量与系统额度，不能把每张图片都算成一个目录监听。

## 入库与失败恢复

目标备份库的多文件批次先分发为单文件任务。每个文件最多执行三次（首次执行加两次指数退避重试），并保留最终失败状态；一次失败不会让同批其他文件一起反复重读。

文件 stat、完整内容 SHA-1 和读取稳定性检查发生在发布锁外。stat 等待上限为 30 秒，摘要读取上限为 5 分钟；取消会销毁只读流，迟到的读取结果不会继续建档。提前关闭但没有正常 EOF 的流必须报错。

准备结果通过数据库短事务发布，与手机上传共用 `ForkIphoneBackup` 锁。事务内只有数据库操作：锁等待上限 10 秒，单条语句及事务空闲上限均为 30 秒。PostgreSQL 负责超时、回滚与释放事务锁；不能在仍可能写库的回调外套一个超时 Promise 后提前放锁。

事务提交后才发送资产创建事件并安排后处理。重复路径保留已有 ID；提交成功但后处理入队失败的重试，会补发已有资产的后处理。没有修改 HTTP API、数据库结构、已发布迁移或官方客户端。

## 验证与边界

关联单测覆盖多根监听、新建嵌套目录、坏文件与好文件并行、stat 超时、摘要取消及提前关闭、下游挂起和重复任务恢复。

`server/test/medium/specs/repositories/external-publication.repository.spec.ts` 在正常 medium 测试模板中创建独立数据库，验证并发发布去重、锁等待超时及部分批次回滚。也可通过 `IMMICH_EXTERNAL_PUBLICATION_TEST_URL` 指定名为 `immich_library_recovery_test` 的独立验收库，复用某个正式版本的空结构；该测试拒绝其他库名，不连接真实图库。

本补丁移除了图库任务长时间持有会话锁的结构性风险。2026-11-20 最初挂起操作尚未复现，不能将其归因于某种图片、ExifTool 或存储故障。源码测试不能替代当前生产版本的独立镜像验收及官方手机真机验收。

## 已部署验收

2026-11-21 经用户授权部署同版本 v3.3.6 候选 `immich-server:library-recovery-48d1a93c1`，启用全部根监听。两座图库实际注册 989、4 个目录，进程有 993 个 inotify 监听，启动无错误；图库队列排空且没有失败。现有截图、原片和预览可读，数据库迁移账本、依赖容器及全部队列暂停标记保持。

同镜像在独立数据库、Valkey 和合成媒体上，经真实 HTTP 客户端验证新建多层目录和后续文件事件，约 5.2～5.7 秒完成入库及预览。发布锁被占用 22 秒时会超时重试，另一座图库继续入库；重启后不重复建档。以上是样本验收结果，实际生产显示时间仍取决于文件写入、读取和后处理负载。官方手机真机与长期全库负载未验证。
